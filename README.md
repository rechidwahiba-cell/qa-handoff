# Site QA Handoff

Try it: **[rechidwahiba-cell.github.io/qa-handoff](https://rechidwahiba-cell.github.io/qa-handoff/)**

No QA team? Test what your developer, agency or freelancer delivers, and send feedback that gets fixed the first time. A starting point for teams of any size.

## What it does

- **A test plan built from your pages**: 24 essential checks per page, or the full plan of 64, in nine categories (content, design, responsive, navigation, forms, SEO, media, accessibility, errors and speed), plus checks for the whole site. Add your own.
- **Guided issue reports**: a failed check opens a report right under it. Pick the kind of problem and the questions adapt: where it is, what you see, what you expected, how serious it is, on which device, with an optional link to a screenshot.
- **A board and a retest loop**: to fix, fixed and to retest, closed. The developer answers each issue, you retest one fix at a time, and a verdict says whether the site can go live.
- **Formats tech teams already use**: a ready-to-paste Jira ticket for every issue, a CSV for Jira, Trello or Asana, Excel, Markdown, a PDF report.
- **Sharing without accounts**: by email, by a link that carries the whole review, or as a file the other person opens in the tool.
- **A "Report this page" bookmark**: select what is wrong on the site you are testing, click, and the issue opens with the address, the selected text and your screen size filled in.
- **A step-by-step demo** that plays a full review on a made-up site.

## How it works

A single HTML file with no framework, no build step and no server. Reviews are saved in the browser as you work and can be saved to a file or packed into a link. Nothing is sent anywhere. It is designed for a laptop or a tablet.

It does not capture screenshots and two people cannot edit the same review at the same time: the review travels as a link or a file.
